用户希望参考 VOZEB-PRO 的前端与模块设计，把短剧工作台升级为更完整、更好用的生产线。经脑暴收敛，**第一期 M4 聚焦：编辑器外观与结构重构（VOZEB 浅色 shadcn 风 + 剪辑式 A 结构）+ 分镜细粒度编辑**，为后续阶段打好外壳。

## 布局结构

```
┌────┬──────────────────────────────────────────┐
│图标│  顶栏：短剧项目 · 状态/积分/头像            │
│栏  ├──────────────────────────────────────────┤
│48px│  项目头卡：← 标题/副标题 · 画幅/镜头数/版本 │
│    │  步骤条：01剧本 02审核 03资产 04分镜* 05生成│
│    ├───────────────────────────────┬──────────┤
│    │  分镜预览（9:16 大帧 + 角标）    │          │
│    │  横向分镜条（缩略图/画词/时长/勾）│  检查器   │
│    │                               │ 分镜|资产 │
│    │                               │ 预算      │
│    └───────────────────────────────┴──────────┘
└────┴──────────────────────────────────────────┘
```

- **图标栏**：剧本 / 资产 / 分镜（当前）/ 生成 等阶段入口。
- **步骤条**：映射既有流水线阶段——剧本(输入/解析) → 审核(review) → 资产(角色绑定) → 分镜(首帧/编辑) → 生成(逐镜视频)。
- **工作区**：选中镜的大预览（首帧/视频）、分镜胶片条、右侧检查器。

## 架构与组件

**新增 `public/drama.css`**：VOZEB 浅色主题，独立文件。`drama.html` 改引 `drama.css`（不再用深色 `styles.css`），避免影响共享样式，零回归。

**重构 `public/drama.html`**：替换现有三栏 `drama-grid` 为「图标栏 + 顶栏 + 步骤条 + 工作区」骨架。

**重构 `public/drama.js`**（约 675 行）按职责拆渲染单元，共享现有 `api()`、状态与轮询：
- `renderStepper()` — 顶部步骤条，按项目状态高亮当前阶段
- `renderPreview()` — 选中镜大预览（首帧图 / 已确认视频）
- `renderStrip()` — 横向分镜条，点击选中
- `renderInspector()` — 选中镜编辑表单（台词/提示词/时长/运镜/换抽/音频模式/连续性）
- `renderAssets()` — 角色资产卡（绑定形象/音色，复用现有 PATCH characters）
- `renderBudget()` — 预算单 + 闸门 A / 闸门 B（复用现有逻辑）

**后端不动**：复用 `lib/drama/routes.mjs`、`pipeline.mjs`、`schema.mjs`、`store.mjs`、`budget.mjs`、`comfyui.mjs`、`llm.mjs`、`agents.mjs` 与 `server.mjs` 挂载。

## 数据模型变更（仅 `normalizeShot` 增 2 字段）

`lib/drama/schema.mjs` 的 `normalizeShot` 新增：
- `audioMode`：`"voice" | "none"`，默认 `"voice"`（配音）。`"none"` 表示该镜静音。M5 才引入 `"原声"`。
- `continuity`：衔接说明字符串（如「与镜 2 同场景」），≤120 字，仅作提示，不参与生成。

二者遵循既有「改台词/时长 → 重算预算并使闸门 A 失效」纪律：编辑 `audioMode`/`continuity` 时复用同一 PATCH 路径与状态守卫。

## 数据流

1. 分镜条点击某镜 → 置为选中镜 → `renderPreview` + `renderInspector` 联动刷新。
2. 检查器编辑 → `PATCH /api/drama/projects/{id}/shots/{shotId}`（既有端点）→ 本地重渲染；若涉台词/时长，触发既有预算重算与闸门失效。
3. 首帧换抽 → 既有 `POST .../shots/{shotId}/frame`（可带 seed）；确认 → `POST .../shots/{shotId}/confirm`。
4. 项目状态沿用现有轮询（`GET /api/drama/projects/{id}`），驱动流水线/闸门/生成进度展示。

## 错误处理

- 沿用统一 JSON envelope（`ok/errorCode/message/retryable`）。
- 状态不可编辑 → 409 冲突提示；首帧/视频未就绪 → 409；费用确认 → 409 `COST_CONFIRMATION_REQUIRED`。
- 换抽/生成失败：落 `failed` 状态，**不自动重试**，由用户决定是否重来（既有纪律）。
- 所有输入经 `normalizeShot` 收敛，非法值回退默认。

## 权衡与风险

- **最大风险**：整页重做的工作量与前端回归。通过「独立样式文件 + 后端不动 + 复用既有接口」把爆炸半径限制在前端三件套。
- **视觉保真**：零框架手写在复杂交互（拖拽、富时间线）上有上限；M4 刻意不实现多轨时间线的拖拽，只做「可点击选镜的分镜条」。
- **范围蔓延**：配音/字幕/合成等诱惑性邻近功能一律留到 M5，M4 只做外壳与分镜编辑。

## 验收标准

1. `npm run check`、`npm run test:unit`、`npm run smoke` 全部通过。
2. `/` 打开短剧编辑器，呈现 VOZEB 浅色风 + 图标栏/步骤条/工作区结构。
3. 分镜条可点击选镜，选中镜在大预览与检查器联动显示。
4. 检查器可编辑台词/提示词/时长/运镜并保存，涉台词/时长时预算按既有规则失效重算。
5. 首帧换抽、闸门 A/B、逐镜视频生成/确认等既有流程在新 UI 下照常可用。
